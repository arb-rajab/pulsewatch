| B-006 | Fix test-fixture cleanup ordering across `scheduler`/`agentapi`/`alerting`/`operatorapi` so a fixture's `DELETE FROM targets`/`alert_channels`/`incidents`/`agents` in `t.Cleanup` doesn't silently fail | Session 22 — **two distinct root causes found and fixed, not one.** (1) Child-before-parent ordering: `check_results`/`incidents`/`check_rollups_hourly` (plain `REFERENCES` to `targets`, no `ON DELETE CASCADE`) and `alert_dispatches` (plain `REFERENCES` to both `incidents` and `alert_channels`) were still present when a fixture's own `DELETE FROM targets`/`DELETE FROM alert_channels` ran, so the delete failed on a foreign-key violation that `_, _ = pool.Exec(...)` silently discarded — exactly R-005's already-documented mechanism, now actually fixed rather than re-described.
